RC7 WINDOWS CHECKOUT REGRESSION
The failed jsoverload/AetherRoute workflow at commit
9c6d23c17f3e8e8ed7a865ba9a1d08b96d84f226 stops at two map checksum tests
before creating an EXE. Both Git map blobs match the expected original LF
bytes. A real temporary Git repository configured with core.autocrlf=true
and core.eol=crlf reproduces the checksum failures for both worlds. Adding
the packaged .gitattributes rule and doing a fresh checkout preserves the
original map bytes; both checksum-validated worlds open successfully.
A release-members test checks that generated source includes that rule and
retains the exact map hashes. No checksum check was disabled or relaxed.
The existing 51 checks still pass. App and PE version metadata are RC7 so
a new v0.9.0-rc7 tag can include the fix rather than moving the old tag.
The full Windows EXE build is still pending a new repository workflow run.
The current GitHub connection has read permission but no push permission.

RELEASE CONTENTS AND LIMITS
The source package includes code/docs, two explicitly configured worlds,
original glyphs/Welcome assets and dependency/runtime notices. Personal
profiles, prompts, routes, screenshots, learned icons, raw upstream database
exports and upstream JavaScript are excluded. The original copyright notice
is retained; third-party map artwork/data keep their original rights.

Runtime/build dependency locks and the existing pinned GitHub workflow are
retained. No dependency update or fresh advisory audit was part of RC6.
No Windows EXE was compiled here. BUILD.cmd and the GitHub Windows workflow
build the unsigned installer and portable application. Before publishing,
check clean-account install/upgrade, live game tracking/focus, launcher
activation, minimized/moved windows, multiple monitors and DPI on Windows.
See RELEASE.txt.
